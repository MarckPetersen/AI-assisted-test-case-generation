# AI-assisted-test-case-generation
The basic idea is to take a set of requirements or another defined test basis and generate relevant test cases according to the test level, test objectives, product criticality and risk we want to address.


Project: AI-Assisted Test Case Generation
From requirements to a structured basis for acceptance
I would like to bring an idea I have been exploring privately into the MoM Lab and develop it as a collaborative project.
The idea is to explore how AI can support the generation of test cases from requirements and other test basis, while respecting established ISTQB terminology, test principles and test design practices.
The ambition is not simply to ask AI to “write some test cases.” The project should explore a more structured approach:
Requirements / Test Basis → Product Criticality & Risk → Test Level & Objectives → AI-assisted Test Design → Test Cases → Traceability → Execution Results → Exit Criteria → Basis for Acceptance
A key part of the project is product criticality and risk. Not every requirement or component needs the same depth of testing. The generated tests should reflect what is critical, what the risks are, which test level we are working at, and what we are trying to demonstrate through testing.
Why?
This addresses a problem I see in real organisations: the people with the necessary business and technical knowledge often don't have enough time to create and document detailed test cases.
At the same time, QA and Test Management are increasingly asked a very simple question:
“Can we approve the system?”
To answer that professionally, we need evidence. We need to understand what was tested, why it was tested, which requirements and risks were covered, the results, and whether the agreed exit criteria have been satisfied.
The project therefore explores whether AI can help us create a structured, risk-based, traceable and ISTQB-aligned test basis that ultimately supports a professional acceptance decision.
Starting small
I already have an early version of this idea that I have been experimenting with privately. Rather than trying to build the complete solution immediately, I would like to move it into the MoM Lab, start small, and develop it openly together with others.
A first experiment could focus on:
Requirements → Product Criticality/Risk → One Test Level → Generated Test Cases → Traceability
From there, we can learn, challenge the assumptions and gradually add more capabilities.
